Revisión de código de `main` (`91430b6`) y metadatos de Supabase Producción consultados **sólo en lectura** el 2 de noviembre de 2026. No se ejecutó SQL de escritura ni se retiró ningún registro. Esta revisión no equivale a una prueba funcional con cuentas reales.

## Protección mínima necesaria antes de habilitar los casos bloqueados

1. Acordar una única fuente persistida por entidad. Para los módulos que sólo guardan datos en `localStorage`, conectar la vista al repositorio existente o usar un espacio de trabajo persistido **con una política específica por área**. No ocultar datos localmente como si el servidor hubiese confirmado un borrado.
2. Preparar una migración incremental, **sujeta a autorización separada**, que impida a perfiles no administradores alterar campos de eliminación y que restrinja `DELETE` físico en `audits`, `risk_items`, `supplier_quality_evaluations`, `quality_cases`, `form_definitions` y `measurement_assets`. Las políticas `ALL` no sirven para distinguir edición de eliminación.
3. Para JSON compartido de Riesgos y Metrología, usar una operación atómica de servidor que compruebe perfil activo, organización, versión del expediente, relaciones y motivo; conserve una marca histórica por ID; y evite que un guardado antiguo lo reactive. La restricción debe impedir también un `UPDATE` directo del JSON que omita registros.
4. Para clientes y proveedores, definir su pertenencia a la organización interna y bloquear desactivación cuando perfiles o expedientes dependan de la empresa. Conservar el ID y sus relaciones; no usar `DELETE` físico.
5. Para Revisión, Formularios, Auditorías y Mejora Continua, conectar las altas y lecturas actuales a los repositorios persistidos antes de ofrecer borrado administrativo. Donde falten `deleted_at`, `deleted_by` y motivo, se requiere ampliación no destructiva aprobada.

**No se autoriza ni se incluye ninguna de estas migraciones en este PR.** Los casos bloqueados permanecen operativos para consulta/captura y sin nuevo botón de borrado. Antes de implementar cada eliminación deben existir pruebas de administrador, usuario interno, cliente, proveedor, otra organización, error y conservación de archivos/versiones.
